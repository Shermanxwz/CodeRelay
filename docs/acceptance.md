# 验收与证据边界

## 可复现自动验收

从锁文件安装：`npm ci`。运行：`npm run check`。发布打包：`npm run package`。

测试层与证据如下：

| 层       | 实际执行内容                                                       | 不代表什么                          |
| -------- | ------------------------------------------------------------------ | ----------------------------------- |
| SQLite   | 真数据库、重开、双连接事务、租约、幂等、权限、分页                 | 没有测试网络文件系统或多租户集群    |
| OAuth    | 真 localhost HTTP、PKCE、CSRF、scope、audience、轮换/撤销、持久化  | 没有登录真实 ChatGPT/Claude 账户    |
| MCP      | 官方 SDK Client，传统 initialize 与 2026-07-28 discovery/list/call | 不替代每个产品客户端的账户实测      |
| 桥接     | 真网关、SQLite、生产插件、临时 Git 仓库、真实验证子进程            | MiniMax Host 明确是测试 fixture     |
| 生命周期 | 原子日志、重复交付、审批、问卷、取消、失租、重启 unknown           | 不保证所有操作系统/宿主缺陷均已发现 |
| 包与容器 | 正式 ZIP/tar 检查、SHA-256、重复打包一致性、非 root 容器启动       | 未部署到用户生产服务器              |

CI 的准确结果与源码 SHA 以 GitHub Actions 运行记录为准。所有模型回复样例都只出现在测试 fixture；生产服务没有模拟 Agent 后备模式。

## 实机验收门槛（尚未完成）

使用已授权、已登录、版本可核对的 MiniMax Code 桌面端，以及一个可丢弃的测试仓库。记录日期、OS、桌面版本、实际 provider/model、项目目录、任务与会话 ID、Git diff、验证退出码和产物校验和，不记录登录凭据。

- [ ] 在真实 MiniMax Desktop 安装 Release 插件，打开页面、配对、绑定当前项目。
- [ ] 从真实 ChatGPT 完成 OAuth，提交一个小修改并取得真实结果。
- [ ] 从真实 Claude 读取同一任务，继续修改并验收。
- [ ] 确认实际模型与 MiniMax 用量页面一致；核对费用，不预先承诺免费。
- [ ] 触发真实工具审批和问卷，确认用户决定绑定正确 session/request。
- [ ] 运行本地验证命令，确认非零退出码确实失败、缺失报告不显示通过。
- [ ] 取消执行、主动断网、重启插件；确认结果不明时锁定且不重跑。
- [ ] 在真实窗口检查界面布局、输入、长文本、窄窗口、权限关闭与升级恢复。

这些条目是稳定正式发布前的实际验收门槛。没有设备/账号证据时不得将它们勾选为通过。首次 Release 保留为 prerelease，方便安装联调。

## 发布条件

提交必须通过对应 SHA 的类型检查、测试、构建、依赖高危审计、打包和容器检查；发布文件要有校验和，并与 tag 的 package/plugin 版本一致。PR 通过后合入 main，删除已合并的临时实现分支。版本标签和 Release 保留，供重现、比较和回滚。
